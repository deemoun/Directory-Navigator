# Directory Navigator

[English](README.md) | [Русский](README.ru.md)

Современный терминальный файловый менеджер на **Rust и Turbo Vision**, вдохновлённый
**DOS Navigator**.

Привычные две панели, классические цвета, сочетания клавиш и управление мышью —
для современных компьютеров. Работает прямо в терминале, без эмулятора DOS
или графической оболочки.

Поддерживает **macOS, Windows и Linux**. Последний опубликованный выпуск
устанавливается с [crates.io](https://crates.io/crates/directory-navigator):
`cargo install directory-navigator`. Необходимые инструменты — в разделе
[«Начало работы»](#начало-работы).

## На основе Turbo Vision

[Turbo Vision for Rust](https://github.com/aovestdipaperino/turbo-vision-4-rust)
используется для файловых панелей, меню, диалогов, редактора, просмотрщика,
утилит и Tetris. Рабочий стол и система контролов отвечают за перемещение окон,
выделение, фокус и обработку ввода. Directory Navigator сохраняет классический
облик DN и добавляет поддержку Unicode и современных файловых систем.

## Возможности

- Просмотр двух каталогов рядом, отметка файлов, копирование, перемещение и переименование.
- Создание каталогов и отправка файлов в корзину с подтверждением.
- Поиск файлов, сравнение каталогов, подсчёт размеров папок и закладки.
- Быстрый просмотр текста и шестнадцатеричных данных, редактирование Unicode и текста в старых кодировках, поиск и замена.
- Читайте оформленный Markdown по F3, редактируйте исходник с подсветкой по F4 и просматривайте несохранённый текст по F5.
- Несколько открытых редакторов и просмотрщиков с переключением через **Alt+0**.
- ZIP/ZIP64, TAR, TAR.GZ/TGZ, 7z и RAR прямо в файловых панелях; F5 извлекает выбранные файлы и папки.
- Создавайте ZIP из выбранных файлов и папок, при желании с паролем AES-256; просматривайте и распаковывайте зашифрованные ZIP внутри DN.
- Запуск команд оболочки из командной строки внизу экрана.
- Настройка интерфейса, часов и заставки; выбор цветов текста и фона отдельных элементов в стиле DN, с наборами Color, B/W и Mono. Настройки сохраняются при выходе.
- Привязка расширений файлов к встроенным редактору и просмотрщику или внешним командам.
- Сведения о выделении, свободном и общем месте на диске внизу файловых панелей.
- Английский и русский интерфейс, независимая настройка формата даты и 12/24-часового времени.
- История команд с поиском, копирование имён файлов и путей во внутренний буфер обмена.
- Калькулятор, таблица символов и настраиваемое пользовательское меню, а также Tetris и Pentix с отдельными сохраняемыми таблицами рекордов.
- Проверка и изменение отдельных Android APK через подключаемый **APK Workshop**: анализ манифеста и DEX, постоянные рабочие проекты, правка ресурсов и манифеста, экспорт без подписи, а при наличии SDK — подпись и работа с ADB/logcat. Работает без apktool; поддерживаемые изменения и требования SDK описаны в [руководстве](docs/USER_GUIDE.md#apk-workshop) (на английском).
- Воспроизведение локальных **MP3, FLAC, WAV и Ogg Vorbis** в macOS, Linux и Windows: плеер в стиле DN с очередью на время сеанса, импортом папок и подпапок, тегами и длительностью треков, перемешиванием, повтором, паузой, перемоткой и громкостью. По умолчанию плагин выключен; включите его в Options → Configuration → Plugins, затем используйте Utilities → Add music to player. Обычная сборка включает поддержку звука. Основан на DOS Navigator от RIT Research Labs.

## Начало работы

### Установка с crates.io — основной способ

[Directory Navigator на crates.io](https://crates.io/crates/directory-navigator) —
основной источник установки для **macOS, Windows и Linux**. Установите стабильный
Rust, Cargo и инструменты сборки для своей платформы.
**В Linux сначала установите пакеты из таблицы ниже:** звук включён по умолчанию,
поэтому Cargo нужны `pkg-config` и файлы разработки ALSA. Затем выполните:

```sh
cargo install directory-navigator
dn
```

Устанавливается последний опубликованный выпуск и команда **`dn`**. Для обновления
повторите ту же команду установки. Проверить установленную версию: `dn --version`.
DN открывает текущий каталог. Минимальный размер терминала — **80 столбцов × 25 строк**.

Cargo собирает программу локально. Необходимые инструменты:

- **macOS:** Xcode Command Line Tools (`xcode-select --install`).
- **Windows:** Rust с MSVC и Visual Studio Build Tools с компонентами
  **Desktop development with C++** и Windows SDK.

**Зависимости сборки со звуком в Linux** — выполните команду для своего дистрибутива
перед `cargo install directory-navigator`:

| Дистрибутив | Инструменты сборки и файлы разработки звука |
| --- | --- |
| Debian / Ubuntu / Linux Mint | `sudo apt install build-essential pkg-config libasound2-dev` |
| Fedora | `sudo dnf install gcc pkgconf-pkg-config alsa-lib-devel` |
| Arch Linux / Manjaro | `sudo pacman -S --needed base-devel pkgconf alsa-lib` |

При ошибке **«The pkg-config command could not be found»** или
**«The system library alsa was not found»** установите пакеты из таблицы и повторите
`cargo install directory-navigator`. Проверка наличия обеих зависимостей:
`pkg-config --modversion alsa`. Для других дистрибутивов нужны пакеты с командой
`pkg-config`, заголовочными файлами ALSA и метаданными `alsa.pc`.

Обычная сборка включает звук; сам Music Player включается отдельно в
Options → Configuration → Plugins. Установка без звуковых библиотек:

```sh
cargo install directory-navigator --no-default-features
```

В таком варианте сохраняются обычные ассоциации и внешнее открытие файлов,
а плеер показывает сообщение о недоступности звука. Готовому Linux-бинарнику
со звуком нужны библиотеки ALSA (`libasound2t64`/`libasound2` или `alsa-lib`)
и настроенное устройство вывода, доступное пользователю. Windows использует
WASAPI, macOS — CoreAudio. Внешний плеер, FFmpeg, ASIO SDK и установка кодеков
не требуются.

### Поддерживаемые платформы и проверки

DN поддерживает **macOS, Windows и Linux**. Работа файлового менеджера проверена
нативно на macOS и подтверждена пользователями на Windows и Linux ARM64.
Изменения для Linux и Windows также проходят автоматические тесты и проверки
кросс-компиляции.

| Платформа | Архитектуры | Проверки |
| --- | --- | --- |
| macOS | Apple Silicon / Intel | Нативные тесты, терминальные сценарии и воспроизведение звука на Apple Silicon |
| Windows 10/11 | x86_64 | Пользовательская проверка файлового менеджера; кросс-компиляция и Clippy |
| Linux | x86_64 / ARM64 | Пользовательская проверка файлового менеджера на ARM64; кросс-компиляция и Clippy для обеих архитектур |

Новый звуковой движок Linux/Windows прошёл проверки кросс-компиляции;
воспроизведение через реальное аудиоустройство пока проверено на macOS.

### Альтернатива: готовый исполняемый файл

Скачайте архив для своей системы и архитектуры из релизов проекта или артефактов
ручных сборок. Распакуйте его и запустите `dn.exe` в Windows. В macOS/Linux:

```sh
chmod +x dn
./dn
```

Для готового бинарника Rust и инструменты сборки не нужны. Загруженные сборки
macOS не подписаны и не нотарифицированы, поэтому система может блокировать их.
Рекомендуемая установка через Cargo собирает программу локально.

### Альтернатива: сборка текущих исходников

С теми же инструментами сборки для своей платформы:

```sh
cargo build --release --locked
./target/release/dn
```

В Windows запускайте `target\release\dn.exe`. Для варианта без звуковых библиотек
добавьте к команде сборки `--no-default-features`. MSVC-сборки Windows статически
подключают C runtime через `.cargo/config.toml`.

### Виртуальные консоли Linux

В настоящей виртуальной консоли Linux (`/dev/ttyN`) DN автоматически использует
запущенную службу GPM для мыши. Установите и настройте пакет `gpm` своего
дистрибутива; самому DN не нужны права root или библиотека `libgpm`. Для вывода
используются совместимые с консолью цвета без изменения системной палитры.
В графических терминалах, SSH и tmux сохраняются обычный ввод мыши и расширенные цвета.

**Utilities → System Information** показывает режим терминала, способ вывода
цветов, источник мыши, ошибки GPM и наличие символов в карте консольного шрифта.
Для кириллицы нужен подходящий шрифт: смена локали сама по себе не добавляет
глифы. DN не меняет шрифты или режим клавиатуры. Подробнее в руководстве:
[GPM и цвета консоли](docs/USER_GUIDE.md#mouse-in-a-linux-virtual-console-gpm)
и [устранение проблем с кириллицей](docs/USER_GUIDE.md#cyrillic-in-a-linux-tty)
(на английском).

## Основное управление

При первом запуске открывается приветственное окно с подсказками по клавиатуре,
справкой и настройками клавиш. Его можно открыть снова через **≡ → Welcome…**.
При наличии сохранённых настроек оно автоматически не появляется.

**Классические сочетания DN используются по умолчанию на всех платформах**, включая
macOS. В **Options → Configuration → Keyboard shortcuts** можно выбрать Classic DN,
Mac-friendly или Automatic. Выбранный профиль сохраняется.

В профиле Mac-friendly нажмите **Ctrl+O**, отпустите клавиши, затем нажмите цифру
или букву. Появится подсказка: **5** — копирование, **4** — редактор, **0** — выход.
**Ctrl+O, K** открывает настройки клавиатуры. Классические клавиши также работают;
`^O5` означает Ctrl+O, затем 5. Необязательный профиль Automatic выбирает
Mac-friendly в macOS и Classic DN на остальных платформах.

| Клавиша | Действие |
| --- | --- |
| Tab | Переключение панелей |
| Стрелки / Page Up / Page Down | Перемещение по списку файлов |
| Enter / Backspace | Открыть выбранный элемент / перейти в родительский каталог |
| Insert / Space | Поставить или снять отметку |
| F1 | Справка |
| F2 | Пользовательское меню |
| F3 / F4 | Просмотр / редактирование |
| F5 / F6 | Копирование / перемещение или переименование |
| Ctrl+O | Показать вывод терминала; Ctrl+O/Esc/Enter возвращает в DN (Mac: Ctrl+O дважды) |
| F7 / F8 | Создать каталог / отправить в корзину или удалить с подтверждением |
| F9 / F10 | Меню / выход |
| Ctrl+F7 / Alt+F7 | Рекурсивный поиск / быстрый поиск по имени |
| Ctrl+Q / Ctrl+T | Быстрый просмотр / дерево каталогов |
| Alt+0 | Переключение между файловыми панелями и открытыми документами |

Один щелчок выбирает элемент, двойной открывает его, Ctrl+щелчок ставит отметку.
В просмотрщике и редакторе F1 показывает справку по текущему окну. В macOS для
функциональных клавиш может потребоваться Fn.

**Manager → Windows…** (Alt+0) переключает между файловыми панелями, редакторами
и просмотрщиками. В профиле Mac-friendly также работает **Ctrl+O, затем U**.
Каждый документ сохраняет собственные изменения, историю отмены, поиск и положение
прокрутки. F4 открывает выбранный файл; повторное открытие активирует уже существующий
документ. Закрытие и выход проверяют несохранённые изменения в соответствующих
редакторах. Редакторы и просмотрщики открываются развёрнутыми; окна можно перемещать,
менять их размер и располагать плиткой (**Tile**) или каскадом (**Cascade**) через
меню Manager или список окон. Геометрию файловых документов можно восстанавливать через настройки сеанса.

Копирование и перемещение используют переключаемое окно **Transfer Center**:
можно продолжать просмотр каталогов и редактирование, пока одна операция выполняется,
а остальные ждут в очереди. **Manager → Transfers…** снова открывает ход выполнения
и результаты. Закрытие окна не останавливает работу; ошибка или отмена приостанавливает
очередь до её возобновления. Замена существующих файлов требует подтверждения;
каталоги можно объединять. Подробнее — в разделе
[о больших файлах и замене](#большие-файлы-и-замена-существующих-файлов).

Нижняя строка — командная. Введите команду и нажмите **Enter**, чтобы выполнить её
в каталоге активной панели; **Esc** очищает строку. **Ctrl+E / Ctrl+X** вызывают
историю команд. `cd "folder name"` меняет каталог активной панели. Если строка пуста,
Enter открывает выбранный элемент. Команды оболочки выполняются с вашими обычными
правами, независимо от подтверждений файловых операций самого менеджера.

## Настройки и работа с файлами

Настройки загружаются автоматически и сохраняются при штатном выходе.
**Options → Save desktop** сохраняет их сразу; **Options → Configuration → System Setup**
управляет сохранением при выходе.

- macOS/Linux: `~/.config/dn/config.conf` или `$XDG_CONFIG_HOME/dn/config.conf`.
- Windows: `%APPDATA%\Directory Navigator\config.conf`.

**Options → Configuration → Language / date & time** меняет язык интерфейса,
порядок даты (год/месяц/день, день/месяц/год или месяц/день/год), разделитель даты
и 12/24-часовой формат времени с настраиваемым разделителем. Apply принимает
изменения, Cancel оставляет прежние настройки. Часы, даты в панелях и сведения
о файлах используют эти параметры. По умолчанию выбраны английский язык,
год-месяц-день и 24-часовое время. Английский и русский каталоги переводов встроены
в программу, отдельные файлы для них не нужны. Непереведённые сообщения выводятся
на английском, а системные ошибки сохраняют исходный текст.

`config.conf` использует TOML с `config_version = 2` и разделами настроек.
Поддерживается только этот формат; старые плоские файлы не преобразуются.
Некорректный файл переименовывается в `_old_config.conf` (с номером, если имя занято),
после чего загружаются значения по умолчанию. При обычном сохранении создаётся новая
конфигурация; недоступные файлы, файлы только для чтения и ошибки восстановления
по-прежнему вызывают сообщения об ошибках. Неизвестные параметры TOML сохраняются.
Автоматически загружается только `config.conf`; `config.txt` игнорируется.

**Options → Import DOS settings…** читает оригинальный `DN.CFG` и показывает
поддерживаемые настройки часов, скрытых файлов, сортировки, подсветки, выделения,
редактора и заставки. Apply применяет их к текущему сеансу; обычное сохранение
записывает их на диск. Cancel ничего не меняет, исходный DOS-файл не изменяется.
DOS-пути, окна рабочего стола, команды, аппаратные настройки и пользовательские
палитры не импортируются; защита корзины и подтверждения сохраняются.
Совместимость проверена на тестовых данных, полученных из исходников;
реальный пользовательский `DN.CFG` пока не проверялся.

По умолчанию удаление отправляет файлы в корзину; ошибка корзины никогда не
приводит к автоматическому безвозвратному удалению. Безвозвратное удаление можно
выбрать в File Manager Setup; подтверждение всё равно требуется. Обнаруженные
изменения поставленных в очередь элементов или их родительских каталогов
останавливают операцию. Отмена или ошибка сохраняет уже выполненную работу;
автоматического отката многофайловых операций нет.

ZIP поддерживает подтверждаемые обновления; другие архивы доступны только для чтения.
Просмотр и редактирование текста ограничены указанными ниже пределами. Важные сценарии
проверяйте на копиях. В сообщении о проблеме указывайте ОС, терминал и шаги
воспроизведения. Подробные сочетания клавиш, ограничения и настройка
пользовательского меню описаны в [руководстве](docs/USER_GUIDE.md) (на английском).

### Ошибки и предупреждения

Ошибки основных файловых команд поясняют действие, путь, известный результат и
следующий шаг. В разделе **Причина** сохраняются исходные сообщения системы или
библиотеки. При сбое передачи часть работы может быть завершена — проверьте Transfer
Center перед повтором. Предупреждение после публикации означает, что файл записан:
оставьте редактор открытым и следуйте подсказке. DN не повторяет операции сам,
не отменяет подтверждения и не запускает другое приложение автоматически.

### Восстановление сеанса

**Options → Configuration → System Setup → Восстанавливать сеанс** предлагает
**Выкл. / Только панели / Панели и документы**. По умолчанию выбраны только панели:
восстанавливаются оба каталога, курсор, фильтр, прокрутка и активная панель. Отметки
файлов очищаются; вместо архива открывается содержащий его каталог.

Режим документов также открывает файловые просмотрщики и редакторы, восстанавливая
позиции и расположение окон. Содержимое перечитывается с диска. Несохранённый текст
защищён обычными подтверждениями и аварийным восстановлением. Пароли, служебные окна,
члены архивов, предпросмотры, передачи и состояние плеера не сохраняются.

**Save desktop** сохраняет снимок сразу; штатный выход — только при включённом
сохранении настроек при выходе. **Load desktop** перечитывает настройки, не заменяя
открытые документы. Команда `dn --no-session` пропускает восстановление и открывает
каталог запуска. Недоступные элементы пропускаются с общим уведомлением. Снимок
хранится в том же защищённом файле настроек: не более 128 документов и 1 МиБ на весь
файл конфигурации.

### Большие файлы и замена существующих файлов

F3 читает большие обычные дисковые файлы ограниченными окнами, поддерживая
прокрутку, переход к строке или байту, End и поиск по всему файлу. Предпросмотр
архивных файлов, PDF и оформление Markdown сохраняют описанные в руководстве
ограничения; большие дисковые Markdown-файлы показываются как исходный текст.
F4 поддерживает до 64 МиБ в Unicode-буфере и записываемых байтах, до 1 000 000 строк.
Слишком большие документы и сохранения отклоняются без усечения содержимого.

При копировании, перемещении и распаковке замена файлов по умолчанию требует
подтверждения: **Заменить / Пропустить / Заменить все / Пропустить все / Отмена**.
Изначально выбрано «Пропустить»; выбор «все» относится только к текущей операции.
Esc отменяет её, сохраняя выполненную работу. Каталоги объединяются рекурсивно,
посторонние файлы сохраняются. Доступны и явные режимы отказа и пропуска конфликтов.
Конфликты файла с каталогом, ссылки и специальные назначения отклоняются.
**«Сохранить как»** предлагает **Заменить / Отмена** с безопасным выбором «Отмена»;
обычный F2 сохраняет проверку внешних изменений.

### Анализ объёма каталогов

**Ctrl+T → Анализ (F5)** считает размеры папок в фоне; открытие дерева само по себе
не запускает рекурсивный обход. **F6** меняет порядок Имя/Размер среди соседних
каталогов после остановки анализа. Размеры и полосы учитывают скрытые файлы;
жёсткие ссылки считаются отдельно, ссылки на каталоги не обходятся. Другие файловые
системы исключаются. Свободное/общее место тома показано отдельно. Стоп или Esc
останавливает анализ, сохраняя явно помеченные частичные итоги; ещё один Esc
закрывает дерево. Обновление помечает затронутые снимки устаревшими. Результаты
живут только в текущем окне дерева. Это размеры файлов, а не занятое или
освобождаемое место. Подробнее — в [руководстве](docs/USER_GUIDE.md#directory-tree-and-disk-usage).

### Большие архивы и обновление ZIP

Поддерживаются архивы до 64 ГиБ и 100 000 элементов с ограниченным объёмом
метаданных. Доступен ZIP64; создание ZIP принимает до 64 ГиБ исходных данных.
Просмотр и распаковка RAR и 7z выполняются внутри DN, включая запрос пароля;
внешний архиватор не нужен. Вложенные и многотомные архивы не поддерживаются.

Откройте ZIP в одной панели и нажмите F5 на дисковых файлах в другой, чтобы
добавить их. Диалог **«Обновление ZIP»** требует явного подтверждения замены
совпадающих элементов. F8 внутри ZIP подтверждает удаление выбранных файлов
и деревьев папок. В обоих диалогах изначально выбрана отмена. F4 открывает
текстовый файл ZIP в частной рабочей папке; F2 сохраняет его через пересборку
ZIP во временный файл, а «Сохранить как» экспортирует обычный дисковый файл.
Остальное содержимое сохраняется; ошибка оставляет исходный ZIP и несохранённый
текст редактора. Для обновления нужно место под новый архив. Другие форматы
доступны только для чтения. Подробнее — [работа с ZIP](docs/USER_GUIDE.md#zip-member-updates)
(на английском).

### Кодировки текста

Просмотрщик и редактор поддерживают UTF-8, UTF-16 LE/BE, CP866, Windows-1251,
KOI8-R и Windows-1252. BOM и корректный UTF-8 определяются автоматически;
для другого похожего на текст содержимого открывается выбор кодировки с
предпросмотром. F8 меняет кодировку; в редакторе файл перечитывается после
обработки несохранённых изменений. F2 сохраняет кодировку, BOM и смешанные
переводы строк. **File → Save with encoding…** явно преобразует формат;
непредставимые символы блокируют запись, а не заменяются. Новые документы
используют UTF-8 без BOM. Подробнее — [кодировки текста](docs/USER_GUIDE.md#text-encodings-in-f3-and-f4)
(на английском).

### Просмотр текста PDF

F3 открывает извлечённый текст PDF внутри DN: страницы, поиск и переход по номеру
страницы. Enter сохраняет внешнее открытие. Поддерживаются файлы внутри архивов.
Для зашифрованного PDF появляется скрытое поле пароля с повторным вводом и отменой.
Пароли PDF и ZIP вводятся отдельно и не сохраняются. Графический просмотр и OCR
пока не реализованы.

### Открытие TXT внутри DN

Включите **Опции → Файловый менеджер → Настройка → Открывать TXT во встроенном
просмотрщике**, чтобы Enter и двойной щелчок открывали `.txt` / `.TXT` внутри DN
на всех трёх платформах. По умолчанию флажок выключен; при включении он имеет
приоритет над ассоциациями TXT. Ctrl+Enter открывает файл внешним приложением.
F3 и F4 сохраняют обычные действия просмотра и редактирования.

### Tetris, Pentix и оригинальные рекорды

Чтобы импортировать таблицы рекордов DOS Navigator, поместите **`dn.tet`**
(или `DN.TET`) рядом с `config.conf`, затем откройте или переоткройте игру.
Обе оригинальные таблицы объединятся с соответствующими Top Ten в `tetris.conf`
без повторного импорта. Исходный файл останется нетронутым. Режим Classic Tetris
или Pentix выбирается в Setup; Pentix использует все 27 оригинальных фигур
из одной–пяти клеток.

DOS-файлы не содержат сведений о кодировке: при первом импорте используется CP437
для английского или CP866 для русского, в зависимости от языка интерфейса.
Выбор запоминается в файле Tetris. Новые рекорды поддерживают имена в Unicode;
если в оригинальной записи нет числа строк, показывается «—».

## Разработка

Подробности реализации — в [документации об основах работы с документами](docs/DOCUMENT_FOUNDATIONS.md)
(на английском).

```sh
cargo fmt --check
cargo clippy -- -D warnings
cargo test
cargo build --release
```

В GitHub откройте **Actions → Build all platforms → Run workflow**, чтобы проверить
и собрать macOS (Apple Silicon и Intel), Linux (x86_64 и ARM64) и Windows (x86_64).
Каждое успешно завершённое задание загружает архив с исполняемым файлом, README
и лицензией MIT, а также контрольную сумму SHA-256. Файлы находятся в разделе
**Artifacts** этого запуска и хранятся 30 дней. Сборки не подписаны; этот процесс
не публикует GitHub Release. **Rust checks** также запускается только вручную:
откройте его в Actions и выберите **Run workflow**. Оба процесса не запускаются
при push, pull request или по расписанию.

### Проверка пакета crates.io

Имя пакета в реестре — `directory-navigator`, исполняемого файла и Rust-библиотеки —
`dn`. Зависимости используют опубликованные версии crates.io, включая неизменённый
Turbo Vision 4.1.0. Адаптеры ячеек терминала и переведённых подписей входят в DN;
форк библиотеки не требуется.

Перед ручной публикацией проверьте `cargo package --list`, выполните
`cargo publish --dry-run` и сверьте версию исполняемого файла. В пакет должны
входить исходники, переводы, тестовые данные, README, изображения документации,
`LICENSE` и `THIRD_PARTY_NOTICES.md`. Пробная публикация не загружает пакет в реестр.

### Общий выпуск для всех платформ

После отправки workflow в основную ветку откройте **Actions → Build unified release
→ Run workflow**, выберите исходную ветку и укажите версию **без `v`**, например
`1.0.0` или `1.1.0-beta.1`.

Ручной процесс проверяет, тестирует и собирает все пять целей: macOS Apple Silicon
и Intel, Windows x86_64, Linux x86_64 и ARM64. Версия встраивается в приложение,
окно About и CLI, затем создаётся **неопубликованный черновик релиза** с тегом
`v<version>`. Предварительные версии отмечаются автоматически.

Для скачивания создаются пять архивов с версией в имени: четыре TAR.GZ и ZIP
для Windows. Каждый содержит исполняемый файл, README, руководство пользователя
и лицензию MIT. Файлы контрольных сумм используются для внутренней проверки
сборок и не прикрепляются к релизу. Имена Linux-архивов:
`dn-<version>-linux-x86_64.tar.gz` и `dn-<version>-linux-aarch64.tar.gz`.

Тег указывает на точное дерево исходников с версией, использованное для всех
сборок. При необходимости отдельный коммит релиза обновляет Cargo.toml/Cargo.lock;
ветка разработки не переписывается, её версия не меняется. Следующую версию ветки
при необходимости задавайте отдельно. Только финальное задание получает право
записи в репозиторий; тег и черновик не создаются, пока не пройдут все пять сборок.
Существующие теги и релизы не перезаписываются. Если публикация завершилась ошибкой
после создания тега или черновика, проверьте эту версию в GitHub: завершите черновик
вручную либо осознанно удалите частичный черновик/тег перед новым запуском.
При восстановлении процесс не удаляет и не заменяет существующие релизы.

Проверьте черновик, скачанные сборки и примечания к выпуску, затем опубликуйте
релиз самостоятельно. Сборки macOS остаются неподписанными и ненотарифицированными;
сборки Windows также не подписаны. Репозиторий должен разрешать Actions запись
содержимого и создание тегов; строгие правила тегов могут блокировать финальное
задание. Все процессы запускаются только вручную, а не при push или создании тега.

### Отдельные сборки Windows и Linux

Эти процессы независимы от общего выпуска и работают только при выборе
**Run workflow**. Выберите исходную ветку и укажите версию без `v`.

| Процесс в Actions | Цели | Файлы в разделе Artifacts запуска |
| --- | --- | --- |
| **Build Windows** | Windows x86_64 | **windows-downloads**: ZIP с `dn.exe` |
| **Build Linux** | Linux x86_64 и ARM64 | **linux-downloads**: два архива TAR.GZ с `dn` |

Оба процесса проверяют, тестируют и собирают приложение, сверяют версию
исполняемого файла и включают README, руководство пользователя, лицензию MIT,
отдельные контрольные суммы SHA-256 и `SHA256SUMS.txt`. Файлы хранятся 30 дней.
Теги, GitHub Releases и черновики не создаются. Указанная версия встраивается
в исполняемые файлы; исходная ветка не меняется. Сборки Windows не подписаны.
Успешная сборка не заменяет проверку в Windows Terminal или терминале Linux.

Тесты вспомогательных скриптов выпуска (Python 3.12+, только стандартная библиотека):

```sh
python3 -m unittest discover -s scripts -p 'test_*.py'
```

Исходники приложения на Rust находятся в `src/`, тесты — в `tests/`.

## Сетевая информация и удалённые файлы

**Утилиты → Сетевая информация** показывает локальные интерфейсы, MAC-адреса,
IPv4/IPv6, шлюзы и DNS-серверы выбранного адаптера. Выпадающий список позволяет
переключать интерфейсы; обновление сохраняет выбор, пока адаптер доступен. Скорости
приёма и отправки обновляются примерно раз в секунду в B/s, KiB/s и более крупных
единицах, учитывая весь трафик выбранного адаптера. Это не проверка скорости Интернета.
После смены адаптера измерение начинается заново; недоступность счётчиков отображается явно. Этот снимок не проверяет доступность Интернета.
Основные пути DN и системы остаются в **Системной информации**.

**Утилиты → Удалённые соединения…** открывает встроенный клиент SFTP, явного
FTPS и FTP. Удалённый каталог открывается в любой панели: F3 — просмотр,
F4 — редактирование с сохранением на сервер, F5 — скачивание или загрузка,
F7 — создание каталога, F8 — окончательное удаление после подтверждения.
Переименование работает с одним элементом. Ctrl+PgUp отключает соединение и
возвращает исходный локальный каталог.

Профили рядом с конфигурацией DN содержат параметры соединения и подтверждённые
отпечатки SSH, но не пароли и не парольные фразы ключей. В списке «Профили»
можно выбрать, изменить, переименовать или удалить профиль с подтверждением. Перед первым входом
проверьте отпечаток; изменившийся сохранённый ключ отклоняется. Предпочитайте
SFTP или FTPS: обычный FTP передаёт пароли и файлы без шифрования. FTPS проверяет
сертификаты и не переключается на незашифрованный FTP при ошибке.

Скачивание использует локальную подготовку и обычные подтверждения замены DN.
Загрузка сначала подготавливает файл на сервере, затем переименовывает его;
гарантии публикации FTP зависят от сервера. Замена через SFTP требует расширения
атомарного переименования. Ссылки не обходятся, исходники при передаче не удаляются.
Прямая передача между двумя серверами и автоматическое восстановление соединений
пока не поддерживаются. **Терминал SSH** запускает установленный клиент OpenSSH
`ssh`, использующий собственные проверки ключей и аутентификацию; после выхода
восстанавливается DN. Рабочий каталог командной строки остаётся локальным.
Подробнее — в [руководстве](docs/USER_GUIDE.md#remote-connections).
